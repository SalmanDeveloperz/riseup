# #37 Your own sounds + sound search

**Phase 7+** · on `development` · no database change (`WakeAlarm.soundName` stores a file name, as before)

## What it does
Sound Picker (Alarm Editor → Sound):
- **Search bar** under the title ("Search sounds"): finds a sound by its name, its description or its group,
  ignoring upper/lower case and accents. "rain" → Thunderstorm ("Heavy rain…") and Rainforest; "cafe" → Paris
  Accordion ("a café waltz"); several words must all match ("world drum"). Nothing found → Apple's "No Results".
- **My sounds** (first group): **Add your own sound** → a menu:
  - **From Files**: any song or recording (MP3, M4A, WAV, AIFF, CAF…) or a video file, from the Files app,
    iCloud Drive, Downloads, AirDrop…
  - **Sound of a Video**: a video from Photos ("Gallery"); its sound is used.
  The new sound is selected and plays right away. Each of your sounds has a **…** button: **Rename**, **Delete**.
- Settings → Default sound shows only RiseUp's sounds (the default is for new alarms; your own are per alarm).

### What happens to a picked file (`SoundClipMaker`, ~0.1 s for a whole song)
1. Only the first seconds are decoded (never the whole file): that's why a 1-hour video is as fast as a ringtone.
2. Silence at the start is skipped (videos often start quietly).
3. Mixed to mono, 44.1 kHz, then **normalised** so a quiet recording is as loud as our sounds.
4. Up to **30 s** is kept (Apple's limit for named alarm sounds). A short "ding" is **repeated** to fill ~30 s.
5. Saved as `.caf` in IMA4, the exact format of our own sounds, in `Library/Sounds` (the only folder AlarmKit
   searches besides the app itself).

### Every case, and what the user sees
| Case | Result |
|---|---|
| Song from Files / video from Photos | added, selected, plays |
| A 4-minute song | its first 30 s (fading out at the end) |
| 4 s of silence, then music | the clip starts with the music |
| A whisper-quiet voice memo | made loud (but never more than ×16, so hiss stays hiss) |
| A 1-second "ding" | repeated with small gaps for ~30 s |
| Not audio ("song.mp3" that's really text), an empty file | "This file can't be played…" |
| A video without sound | "This video has no sound." |
| Silence (or nothing audible in the first 30 s) | "We couldn't hear anything in its first 30 seconds." |
| A click under ¼ s | "This sound is too short to wake anyone up." |
| An Apple Music song (copy-protected) | "This song is copy-protected…" |
| A video only in iCloud, no internet | "That video couldn't be loaded…" |
| 50 sounds already | "You've added 50 sounds. Delete one to add another." |
| Delete a sound an alarm uses | blocked: "… is the sound of an alarm. Choose another sound for it first." |
| Its file vanished anyway | iOS rings its own alarm tone (`AlarmSoundRule`); in the app, Digital plays |
| App killed while adding | the half-made file (`.importing-…`) is cleaned up on the next launch |
| The names list (JSON) damaged | every sound still works, named "My sound" |
| Two sounds named the same | "Song", "Song 2" |

## Design decisions (WHY)
- **A clip, not the whole song:** Apple's limit for named alarm sounds is 30 s, and decoding only the start is
  what makes adding instant.
- **`Library/Sounds`:** the app bundle is read-only, so it's the only place AlarmKit can find a user's sound.
- **⚠️ Real-iPhone risk:** developers on Apple's forums report that AlarmKit sometimes plays its default tone
  instead of a `Library/Sounds` file (iOS 26.0). If Salman's iPhone does that, the alarm still rings loudly,
  and the user's sound plays the moment RiseUp opens (Ringing screen). It can never be silent.
- **Files are the truth, JSON only adds names:** nothing an alarm needs can be lost with the JSON.
- **Delete is blocked while in use:** quietly switching alarms to another sound would surprise the user.
- **No permissions needed:** the Files and Photos pickers hand over only what the user picked.
